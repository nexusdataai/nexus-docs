    Platform Architecture¶

    This page provides a comprehensive overview of the Totogi CallSense Platform architecture, including high-level system design, deployment architecture, and data flow patterns.

    Overview¶

    The Totogi CallSense Platform is an enterprise-grade AI-powered call processing and analytics platform that delivers:

    • 100% automated QA coverage of all calls (vs. 30% manual coverage)
    • Real-time AI insights on sentiment, compliance, and performance
    • Multi-million dollar revenue impact with measurable ROI
    • Automated quality assurance and compliance monitoring
    • Real-time sentiment analysis and coaching recommendations
    • Salesforce and Office 365 integration

    Repository Structure¶

    The platform consists of three primary repositories:

    Repository Application Purpose Technology Stack
    starhub-ui Totogi CallSense Analytics Dashboard & Visualization React 18, TypeScript, Vite, Tailwind CSS, Recharts
    starhub-backend Totogi CallSense Call Processing & MCP Server Python 3.11+, FastAPI, boto3, MCP Protocol
    starhub-deployer Totogi Toolkit Deployment Wizard & AWS Orchestration React + Python FastAPI + Electron

    Repository Mapping¶

    Application 1: Totogi CallSense
├── starhub-ui (Frontend)
│   └── React-based analytics dashboard
└── starhub-backend (Backend)
    └── Python-based call processing engine

Application 2: Totogi Toolkit
└── starhub-deployer (Complete Application)
    ├── Frontend (React wizard)
    ├── Backend (Python orchestrator)
    └── Desktop (Electron wrapper)

    StarHub Backend (Call Processing Engine)¶

    Technology Stack: - Framework: Python 3.11+, FastAPI - Protocol: Model Context Protocol (MCP) with HTTP Gateway - AWS SDK: boto3 for AWS service integration - AI: OpenAI GPT for transcription and analysis

    MCP Tools: | Tool | Description | |------|-------------| | journeys_tool | Journey, stage, and job management | | logs_and_reports_tool | Logs and report generation | | wxcc_simulator_tool | WXCC simulator operations | | license_tool | License activation and validation |

    REST APIs: | Endpoint | Description | |----------|-------------| | /api/v1/journeys/* | Journey management | | /api/v1/license/* | License management | | /api/v1/simulator/* | WXCC Simulator APIs | | /api/v1/analytics/* | Analytics and metrics | | /api/v1/calls/* | Processed calls data | | /health | Health check |

    Call Processing Stages: 1. Fetch Tasks - Retrieve tasks from Webex CC 2. Deduplication - Check for already-processed tasks 3. Process Recordings - Download, transcribe, upload 4. Register Metadata - Create metadata and Glue partitions 5. AI Analysis - GPT-powered call analysis

    AWS Deployment Architecture¶

    The complete infrastructure deployed by StarHub Deployer:

    VPC Architecture¶

    • VPC CIDR: 10.0.0.0/16
    • Public Subnet: ALB, NAT Gateway
    • Private Subnet: ECS Fargate, RDS (optional)

    Compute Layer¶

    • ALB: Application Load Balancer for traffic distribution
    • ECS Fargate: Serverless container execution
    • EventBridge: Event-driven automation

    Storage Layer¶

    • S3 Buckets: call-data, wxcc-simulator, deployment artifacts
    • DynamoDB: Transformation system, license, tracking tables

    Security & Identity¶

    • Cognito: User authentication and authorization
    • Secrets Manager: API keys and credentials
    • SSM Parameter Store: Configuration management

    Monitoring & Analytics¶

    • CloudWatch: Logs, metrics, alarms, dashboards
    • Athena: SQL analytics on S3 data
    • Glue: Data catalog and ETL

    Content Delivery¶

    • CloudFront: CDN for frontend distribution
    • S3 Static Hosting: Frontend assets

    Deployment Options¶

    Component Option 1 Option 2
    Frontend CloudFront + S3 AWS Amplify
    Backend ECS Fargate EKS (Kubernetes)
    Database DynamoDB RDS PostgreSQL

    Security Architecture¶

    Authentication & Authorization¶

    Authentication Layer: - Cognito User Pool: Primary identity provider - MFA: TOTP/SMS multi-factor authentication - SSO: SAML/OIDC integration - License Validation: Cryptographic validation

    Authorization Layer: - Role-Based Access Control (RBAC) - Administrator: Full access - Operator: Deploy and manage - Viewer: Read-only access

    Data Protection: - Encryption at Rest: AES-256 (S3, DynamoDB) - Encryption in Transit: TLS 1.2+ - Secrets Management: AWS Secrets Manager - IAM Roles: Least privilege principle - Audit Logging: CloudWatch Logs + CloudTrail

    Security Features¶

    Feature Implementation
    Authentication AWS Cognito with MFA support
    API Security API Key + JWT tokens
    Encryption at Rest AES-256 (S3, DynamoDB)
    Encryption in Transit TLS 1.2+
    Secrets Management AWS Secrets Manager
    Audit Logging CloudWatch Logs + CloudTrail
    License Enforcement Cryptographic validation
